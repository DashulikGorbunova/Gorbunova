# Инструкция по использованию JWT авторизации в Swagger

## Проблема: "Замочек" не работает

Если кнопка авторизации (🔒) не отображается или не работает в Swagger, следуйте этой инструкции.

## Как использовать JWT авторизацию в Swagger

### Шаг 1: Получите JWT токен

1. Откройте Swagger UI (обычно `http://localhost:5000` или `https://localhost:5001`)
2. Найдите endpoint `POST /auth/login`
3. Нажмите "Try it out"
4. Введите любые данные (для демо принимаются любые учетные данные):
   ```json
   {
     "username": "admin",
     "password": "password123"
   }
   ```
5. Нажмите "Execute"
6. Скопируйте значение `token` из ответа

### Шаг 2: Авторизуйтесь в Swagger

1. Нажмите на кнопку **"Authorize"** (🔒) в правом верхнем углу Swagger UI
2. В поле "Value" введите токен в формате:
   ```
   Bearer ваш_токен_здесь
   ```
   **Важно:** Обязательно добавьте слово `Bearer` и пробел перед токеном!
   
   Пример:
   ```
   Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiJhZG1pbiIsImV4cCI6MTYzODM2ODAwMH0.xxx
   ```
3. Нажмите "Authorize"
4. Закройте окно авторизации

### Шаг 3: Используйте защищенные endpoints

Теперь вы можете использовать защищенные endpoints:
- `POST /product` - создание продукта
- `PUT /product/{id}` - обновление продукта
- `DELETE /product/{id}` - удаление продукта
- `POST /category` - создание категории
- `PUT /category/{id}` - обновление категории
- `DELETE /category/{id}` - удаление категории

## Проверка работы

### ✅ Правильно настроено:

1. Кнопка "Authorize" (🔒) видна в Swagger UI
2. После авторизации защищенные endpoints работают
3. В заголовке запроса добавляется `Authorization: Bearer <token>`

### ❌ Проблемы и решения:

#### Проблема 1: Кнопка "Authorize" не видна

**Решение:**
- Проверьте, что Swagger включен в `Program.cs`:
  ```csharp
  if (app.Environment.IsDevelopment())
  {
      app.UseSwagger();
      app.UseSwaggerUI();
  }
  ```

#### Проблема 2: Токен не принимается

**Решение:**
- Убедитесь, что добавили `Bearer` перед токеном
- Проверьте, что токен не истек (действителен 1 час)
- Получите новый токен через `/auth/login`

#### Проблема 3: Получаю 401 Unauthorized

**Решение:**
1. Проверьте формат токена: `Bearer <token>`
2. Убедитесь, что токен не истек
3. Получите новый токен
4. Проверьте настройки JWT в `appsettings.json`

## Настройка JWT

### appsettings.json

```json
{
  "Jwt": {
    "Issuer": "appone",
    "Audience": "appone",
    "Key": "very-secret-key-change-me"
  }
}
```

**Важно:** В продакшене используйте сложный секретный ключ!

## Пример полного процесса

### 1. Получение токена

**Request:**
```http
POST /auth/login
Content-Type: application/json

{
  "username": "admin",
  "password": "password123"
}
```

**Response:**
```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "expires": "2024-01-01T12:00:00Z"
}
```

### 2. Использование токена

**Request:**
```http
POST /product
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
Content-Type: application/json

{
  "name": "New Product",
  "price": 99.99,
  "quantity": 10
}
```

## Отладка

### Проверка токена

Можно декодировать JWT токен на сайте https://jwt.io для проверки содержимого.

### Логирование

Все ошибки авторизации логируются через `ILogger`:
- Неудачные попытки входа
- Ошибки валидации токена
- Проблемы с авторизацией

## Безопасность

⚠️ **Важно для продакшена:**

1. Используйте сложный секретный ключ
2. Настройте HTTPS
3. Ограничьте время жизни токена
4. Используйте refresh tokens для долгоживущих сессий
5. Реализуйте проверку пользователей в базе данных

## Резюме

1. Получите токен через `POST /auth/login`
2. Нажмите "Authorize" (🔒) в Swagger
3. Введите `Bearer <ваш_токен>`
4. Используйте защищенные endpoints

Если проблема сохраняется, проверьте:
- Настройки Swagger в `Program.cs`
- Конфигурацию JWT в `appsettings.json`
- Логи приложения для ошибок
